# CONFIGURE_PROXY.md

# Configuring the Coirtx Proxy

This document explains how to configure the **Coirtx Server** to communicate with a newly installed **Coirtx Proxy**.

> **Prerequisites**
>
> Before following this guide:
>
> * The proxy has been built and installed.
> * The proxy service is running.
> * The proxy can reach the Coirtx Server over the network.
> * The server and proxy are running the **same Coirtx/Zabbix major version**.

---

# Overview

The configuration process consists of:

1. Register the proxy
2. Verify proxy connectivity
3. Assign hosts to the proxy
4. Configure templates
5. Verify data collection
6. Troubleshoot common problems

---

# 1. Register the Proxy

Log in to the Coirtx web interface.

Navigate to:

```
Administration
    → Proxies
```

Click

```
Create Proxy
```

---

## Proxy Settings

Configure the following.

| Field       | Value                        |
| ----------- | ---------------------------- |
| Name        | OIRT-CCTV-PROXY              |
| Mode        | Active                       |
| Proxy group | None (or choose one if used) |
| Description | Optional                     |
| Enabled     | Yes                          |

Click **Add**.

---

## Important

The **Name** entered here **must exactly match** the value configured on the proxy.

Example:

```ini
Hostname=OIRT-CCTV-PROXY
```

located in

```
/etc/coirtx/zabbix_proxy.conf
```

The comparison is **case-sensitive**.

Examples:

Correct

```
Hostname=OIRT-CCTV-PROXY
```

Proxy name

```
OIRT-CCTV-PROXY
```

Incorrect

```
Oirt-CCTV-Proxy
```

or

```
oirt-cctv-proxy
```

A hostname mismatch prevents the proxy from downloading its configuration.

---

# 2. Verify Proxy Connectivity

After the proxy has been created, return to

```
Administration
    → Proxies
```

Within a few moments the proxy should appear as

```
Online
```

The "Last seen" time should continue updating automatically.

If the proxy remains Offline, refer to the Troubleshooting section at the end of this document.

---

# 3. Create or Edit Hosts

A proxy only collects data for hosts that are explicitly assigned to it.

Open

```
Data collection
    → Hosts
```

Either

* Create a new host

or

* Edit an existing host

---

# Example: CCTV NVR

Example configuration.

## Host

```
Host name:
CCTV-NVR-01
```

Visible name

```
CP Plus NVR
```

---

## Host Group

Example

```
CCTV Infrastructure
```

---

## Interface

For SNMP devices

| Setting    | Value       |
| ---------- | ----------- |
| Type       | SNMP        |
| IP Address | 192.168.1.2 |
| Port       | 161         |

---

## Monitored By

Select

```
Proxy
```

Then choose

```
OIRT-CCTV-PROXY
```

This instructs the server to send all polling jobs to the proxy instead of polling the device directly.

---

# 4. Attach Templates

Without templates (or manually created items), the host has nothing to monitor.

Open

```
Templates
```

Attach the appropriate template.

Examples

Linux server

```
Linux by Coirtx agent
```

Network switch

```
Network Generic SNMP
```

CCTV NVR

```
Template CCTV NVR SNMP
```

If a dedicated template has not yet been created, attach no template and create test items manually.

---

# 5. Configure Host Macros

Many SNMP templates require the SNMP community string.

Open

```
Macros
```

Add

| Macro             | Value        |
| ----------------- | ------------ |
| {$SNMP_COMMUNITY} | oirt-monitor |

This value must match the SNMP configuration on the device.

---

# 6. Verify Item Creation

Open

```
Data collection
    → Hosts
```

Select your host.

Open

```
Items
```

You should now see all items inherited from the attached template.

Example

```
System uptime

CPU usage

Memory usage

Disk status

Network interfaces
```

If only one manual test item exists, only that item will appear.

---

# 7. Verify Data Collection

Navigate to

```
Monitoring
    → Latest data
```

Select the host.

Within one or two update intervals, values should begin appearing.

Example

```
System uptime

52784200
```

or

```
CPU Usage

17 %
```

The "Last check" column should continue updating automatically.

---

# 8. Verify Host Availability

Open

```
Data collection
    → Hosts
```

Availability indicators should gradually change.

Examples

SNMP

```
Green
```

means SNMP polling is working.

Grey

means no SNMP item has been checked yet.

Red

means polling failed.

---

# 9. Verify the Proxy is Polling

On the proxy machine, monitor the log.

```
tail -f /var/log/coirtx/coirtx_proxy.log
```

During normal operation you should observe messages indicating:

* configuration synchronization
* item polling
* history uploads
* successful communication with the server

Repeated errors should be investigated immediately.

---

# 10. Verify from the Server

On the Coirtx Server

```
Monitoring
    → Latest data
```

Search for

```
CCTV-NVR-01
```

The latest values displayed here originate from the proxy.

The server does **not** contact the NVR directly.

Communication path

```
Coirtx Server
        │
        │
        ▼
OIRT-CCTV-PROXY
        │
        │
        ▼
CCTV-NVR-01
```

# Troubleshooting

## Proxy Offline

Possible causes:

* Proxy service not running
* Wrong server IP
* TCP port 10051 blocked
* Hostname mismatch
* Version mismatch

Check

```
systemctl status coirtx-proxy
```

and

```
journalctl -u coirtx-proxy -f
```

---

## "Proxy and server major versions do not match"

Both components must use the same major version.

Example

```
Server 8.0.x
Proxy 8.0.x
```

Do not mix

```
Server 8.x
Proxy 7.x
```

or

```
Server 7.x
Proxy 8.x
```

---

## Host Shows Grey SNMP Icon

Usually means:

* No SNMP items exist.
* No template has been attached.
* The first polling cycle has not completed.

Create a manual SNMP item if necessary to verify connectivity.

---

## No Values in Latest Data

Verify:

* The host is assigned to the proxy.
* The proxy is Online.
* The correct template is attached.
* SNMP community is correct.
* The device responds to:

```
snmpwalk -v2c -c <community> <device-ip> 1.3.6.1.2.1.1
```

If `snmpwalk` succeeds from the proxy but Latest Data remains empty, check the proxy log for polling or synchronization errors.

---

## Host Assigned to the Wrong Monitoring Mode

Ensure

```
Monitored by
```

is set to

```
Proxy
```

and that the correct proxy is selected.

Otherwise, the server will attempt to poll the device directly, which usually fails for devices located on a remote network behind the proxy.

---

# Configuration Complete

The Coirtx Proxy is now fully integrated with the Coirtx Server.

The monitoring workflow is:

```
Device
      │
      ▼
Coirtx Proxy
      │
      ▼
Coirtx Server
      │
      ▼
Web Interface
```

Once hosts have been assigned to the proxy and appropriate templates have been attached, monitoring data will begin appearing automatically in **Latest Data**, **Dashboards**, **Problems**, and **Graphs**.
